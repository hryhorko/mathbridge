1. Project Vision & Architecture

MathBridge is an advanced, production-tested EdTech infrastructure designed to bridge the gap between rigorous, abstract university-level mathematics and practical, code-driven engineering application. By moving away from traditional static textbook models, MathBridge transforms engineering mathematics (Linear Algebra, Calculus, Differential Equations) into an active, experimental science environment.

Our core technical innovation lies in the architecture connecting the Learning Management System (LMS) with the computational backend. We developed a seamless integration framework between ATutor LMS and JupyterHub utilizing a Single Sign-On (SSO) mechanism based on JSON Web Tokens (JWT). Upon secure web authorization, users get immediate, seamless access to isolated workspace sandboxes deployed via JupyterHub's DockerSpawner.

3. Benchmarking & Experimental Verification

Status: Working MVP & Fully Validated

The entire platform is operational and has undergone rigorous laboratory evaluation under local simulated workloads. Our experimental research focused on measuring system performance and user transition delays yielded critical performance insights:

  • SSO Authentication Overhead: Empirical testing demonstrates that the JWT-based single sign-on authentication processing time is virtually instantaneous and resource-negligible.
  • Container Initialization: The primary infrastructural latency is strictly bound to the backend DockerSpawner container allocation and kernel instantiation phase.
  • Load Viability: The collected data confirms that the current local implementation is highly efficient and stable for educational institutions operating under moderate concurrent loads (up to 10-15 active sandbox tasks).

4. AWS Cloud Scaling Blueprint & Roadmap (2026–2028)

We are currently actively seeking grant-based resource allocation to scale the platform into cloud-hosted infrastructure for a real-world pedagogical experiment at Ternopil Ivan Puluj National Technical University (TNTU), testing the environment on hundreds of simultaneous active engineering students.

Target AWS Specifications for the Pilot Phase:

  • Compute Resources: 1x Amazon EC2 Compute Instance (m6i.2xlarge framework containing 8 high-performance vCPUs and 32 GB RAM architecture).
  • Storage Layer: 150 GB Amazon EBS (gp3 SSD) attached block layer to secure persistent user scripts, Jupyter notebook changes, and home directory preservation.
  • Automation: AWS Cron-driven scaling policies to safely restrict active execution loops to real university class timetables (~120 hours/month), protecting credit quotas.
